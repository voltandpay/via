### 새로 발견한 것 (설계에 반영할 것)

1. **선택권 있는 앱은 사랑받고, 어쩔 수 없이 쓰는 앱은 미움받는다.** 여러 사업자를 묶고 혜택을 주는 통합 앱(일렉베리 4.79, EVSIS 4.72, 모두의충전 4.61)과, 아파트에 깔려 있어 어쩔 수 없이 쓰는 사업자 앱(이지차저 1.43, KEPCO PLUG 1.53, 차지비 1.58, 파워큐브 1.58)의 별점이 정반대다. 이 패턴은 **글을 남기지 않은 사용자까지 포함한 양쪽 스토어 전체 평점에서도 유지된다** (예: iOS 일렉베리 4.82·모두의충전 4.57 vs 차지비 1.47·EV이음 1.28·파워큐브 1.38).
2. **집 충전은 요금을 고를 수 없다.** 아파트에 설치된 사업자의 요금을 그대로 내야 해서, 같은 완속 전기가 아파트에 따라 145원~320원으로 갈린다. → 요금 최적화가 실제로 작동하는 곳은 **공용 충전(외부·장거리)** 이다.
3. **"회원가를 받기 위한 장벽"이 독립된 불편이다.** 비회원가가 2배라 가입을 강요받지만, 가입·카드 등록·실물카드 발급이 실패하거나 늦어 결국 비회원가를 낸다. 운전자는 평균 4~5개 사업자 멤버십을 보유한다.
4. **"운전 → 보상"에는 이미 선례가 있고, 폰 앱이라 실패하고 있다.** 모두의충전 "캐시백 드라이빙"(주행 km당 포인트)은 **수동 시작·종료와 GPS 오류**로 주행거리가 0으로 기록되는 불만이 반복되고, 2025년에 km당 10원 → 5원으로 줄어 반발을 샀으며, App Store 리뷰에 따르면 결국 **"사전공지 없이 삭제"** 됐다. → **차량 주행거리(Odometer)로 자동 검증하는 차량 앱이 구조적으로 더 낫다.** 우리 아이디어의 가장 강한 차별점. 동시에 **리워드 재원이 지속 가능하지 않으면 기능 자체가 사라진다**는 경고이기도 하다 (보상 재원 설계가 필수).
5. **충전기 고장이 설문상 1순위 불편이다.** GS차지비 1,400명 조사에서 52.7%. 앱 리뷰에서는 앱 오류에 묻혀 비중이 낮게 나오지만(채널 편향), 설계에서 빼면 안 된다.
6. **현대차그룹 앱은 2025년 통합 이후 반발이 크다.** 블루링크 → 마이현대, 기아 커넥트 → Kia App 통합 후 느려진 반응, "1초 길게 누르기", 늘어난 메뉴에 공감 수백~1,500개짜리 리뷰가 몰렸다. → 우리 차량 앱은 **적은 단계, 빠른 반응**이 원칙이어야 한다 (Pleos 심사 기준 0.25초와도 일치).

### 설계에 대한 시사점 (제안)

| 기획 요소 | 판단 | 이유 |
|---|---|---|
| 공용 충전 요금 최적화 (A의 몸통) | **유지·강화** | H1이 가장 강하게 지지됨. 대상은 공용 충전 |
| 회원가·로밍가 반영 추천 | **추가** | "내가 가진 멤버십으로 가장 싼 충전기" — 가입 장벽 회피 |
| 고장·사용 가능 상태 반영 | **추가** | 설문 1순위 불편. 외부 데이터 필요 (6절) |
| 장거리 충전 계획 | **유지 (상황 한정)** | 명절·주말·겨울 장거리에 가치 집중 |
| 통행료 합산 "총 이동비용" | **축소 또는 제거** | H3 근거 없음 |
| 운전 → 보상 리워드 | **유지·차별화** | 차량 센서 자동 검증 = 폰 앱 캐시백 드라이빙의 약점 해결 |
| 리워드 가치 안정성 | **설계 원칙으로** | 축소·소멸·사용 불가에 대한 반발이 큼 |
| 충전 대기 중 게임 레이어 | **재설계 필요** | 차 안에서 기다리는 상황이 드묾. 정차 중 요약·주간 리포트로 이동 검토 |
| 전비 원인 XAI 설명 | **축소** | H5 약함. "남은 거리·예상 비용"으로 전환 검토 |

## 3. ② 앱 리뷰 VOC 분석

> 수집부터 분석까지 전 과정은 앱 리뷰 VOC 리포트 3종에 있다. 이 절은 가설 검증에 필요한 요약이다.
> - ① **[국내 리포트](앱리뷰-VOC-국내-리포트.md)** — 38개 앱 전체 결과, 분류 정확도 검증, Gemini 감성분석
> - ② **[해외 리포트](앱리뷰-VOC-해외-리포트.md)** — 미국·영국 30개 앱, 58,986건
> - ③ **[국내·해외 비교 요약](앱리뷰-VOC-국내해외-비교.md)** — 기획에 쓸 비교와 시사점
>
> 이 절의 키워드 기반 비중은 **하한값**이다(① 5-4절). 가설 판정을 보강하는 결과: H1·H6 — 국내 충전 앱에서 요금 언급의 63%, 리워드 언급의 89%가 긍정(아껴주고 보상하는 기능이 만족 동인), 리워드 언급률 국내 13.2% vs 해외 0.7%, 요금 구조 불만(H1)은 해외에선 드묾. 보상 재원 모델(⑤)의 해외 선례(Optiwatt·ev.energy)는 **차량 연결 실패**가 1순위 불만이어서, 차량 안 Vehicle SDK 기반 설계가 차별점이 된다(③ 6절).

- 분류: 키워드 기반 다중 라벨 18개 카테고리 + 가설 패턴 7개 (분류 체계 v2). 카테고리별 무작위 12건을 직접 읽어 정밀도를 점검하고 오탐(예: "회원가입"이 "회원가"로, "앱이 작동 안 돼"가 충전기 고장으로, "로딩 기다리다"가 충전 대기로 잡히는 문제, 내비의 "배터리"가 휴대폰 배터리인 문제)을 수정했다. 정밀도 표는 [① 국내 리포트 5-3절](앱리뷰-VOC-국내-리포트.md#5-3-정확도-검증-정밀도).

## 4. ③ 커뮤니티 정성 조사

**장거리·명절 (H2)**
- 명절 휴게소는 충전기 1대에 여러 대가 줄을 서서 대기 포함 1~2시간을 허비하기 쉽다 (서울경제).
- "주말이나 연휴엔 고속도로 충전이 쉽지 않더라구요" (클리앙).
- 겟차 장거리 후기: 연휴에 휴게소 3곳에서 충전 실패, 횡성휴게소 6대 충전 중·다른 곳 대기 2대씩. 밤·영하에서 100kW 충전기가 40~50kW로 떨어짐. 목적지에 5% 남기고 도착. **충전사업자 앱 가입·카드 연결에 20분 허비**. 고장 1대.
- 휴게소 전력 용량(1,000kW) 제한으로 200kW 충전기도 제 속도를 못 낸다는 보도.

**겨울 전비 (H5)**
- 환경부 인증 42개 모델 분석: 상온 대비 영하 6.7도에서 주행거리 평균 82km(21%) 감소 (2024-01 보도).
- 오너들은 원인(히터)을 이미 알고 있다 — "전비를 통제할 수 있는 건 사실상 난방밖에 없다", "배터리가 떨어지면 히터부터 끈다". 일부는 무시동 히터를 단다.
- → 니즈는 "왜 떨어지나"가 아니라 **"겨울에 얼마나 갈 수 있나, 얼마나 드나"**.

**요금·멤버십 (H1)**
- 같은 200kW 충전기에서 40kWh 충전 시 자사 회원 13,800원 vs EV이음 로밍 15,724원 (2026-08 공개 요금표 기준 계산).
- 월 200kWh 충전 시 회원가 적용만으로 연 15만 원 이상 차이 추정.
- 클리앙 이용자: 집 충전용 앱과 제조사 앱만 쓰고 환경부 카드는 백업으로 — **가입·카드 수를 최소화**하려는 경향.

**충전 대기 (H4)**
- "충전 대기 중 지루함"을 다룬 글은 찾지 못했다. 대기 불만은 지루함이 아니라 **줄·고장·속도**에 관한 것이다.
- 신규 급속충전기는 80%·50분 제한, 급속 구역 1시간 이상 주차 시 과태료 10만 원.

## 5. 한계

- **채널 편향**: 앱 리뷰는 "앱 품질" 불만에 치우친다. 충전기 고장·대기처럼 앱 밖에서 일어나는 불편은 리뷰에서 과소 대표된다 → 설문(GS차지비 52.7%)과 함께 봐야 한다.
- **App Store 리뷰는 표본이 작다**: Apple 공개 피드가 비어 있어 앱 공개 페이지의 약 10건씩(356건 분석)만 반영했다. 대신 iOS 전체 평점 통계로 앱별 평가는 보완했다.
- **리뷰 작성자 편향**: 3-7절처럼 리뷰 본문 평균이 전체 평점보다 훨씬 낮다. 비중은 불만층 안에서의 상대 순위다.
- **키워드 분류**: 문맥을 완벽히 읽지 못한다. 샘플 점검으로 주요 오탐은 고쳤지만, 비율은 ±수 %p 오차가 있다고 봐야 한다.
- **리뷰어 ≠ 전체 운전자**: 불만이 있을 때 리뷰를 쓰는 경향. 특히 H4·H5처럼 "당연하게 여기는 불편"은 리뷰로 잘 드러나지 않는다 → **인터뷰로 보완 필요**.
- 설문 출처마다 표본·문항이 달라 수치를 직접 비교할 수 없다.

## 7. 데이터·재실행

```
research/voc/
├── scripts/
│   ├── apps.py            # 수집 대상 38개 앱 (그룹·이름·Play ID)
│   ├── find_apps.py       # Play 검색으로 앱 ID 찾기
│   ├── collect_play.py    # Play 리뷰 수집 (앱별 JSONL, 재실행 시 완료 앱 건너뜀)
│   ├── find_ios.py        # iTunes Search API로 iOS 앱 ID 찾기
│   ├── collect_ios.py     # App Store 공개 리뷰 페이지 수집 (앱당 약 10건)
│   ├── ios_ratings.py     # iTunes Lookup API로 iOS 전체 평점·평가 수
│   ├── taxonomy.py        # 불편 18개 카테고리 + 가설 7개 패턴
│   └── analyze.py         # 분류·집계·인용문 추출
├── data/
│   ├── play/*.jsonl       # Play 원본 리뷰 141,767건 (+ _play_meta.json 전체 평점)
│   ├── ios/*.jsonl        # App Store 리뷰 376건
│   └── ios_ratings.json   # iOS 전체 평점
└── out/
    ├── classified_reviews.csv   # 분석 대상 32,662건 + 라벨 (엑셀에서 열람 가능)
    ├── apps_overview.csv        # 앱별 리뷰 수·별점·부정 비율
    ├── ratings_vs_reviews.csv   # 전체 평점(Play·iOS) vs 리뷰 본문 평균
    ├── pain_by_group_all.csv / pain_by_group_recent.csv
    ├── summary.json             # 추이·가설·스토어별 집계
    └── quotes.json              # 카테고리·가설별 대표 리뷰
```

재실행 (프로젝트 루트에서, google-play-scraper·pandas가 설치된 Python):
```bash
python -I research/voc/scripts/collect_play.py research/voc/data/play
python -I research/voc/scripts/collect_ios.py research/voc/data/ios_search.json research/voc/data/ios
python -I research/voc/scripts/ios_ratings.py research/voc/data/ios_search.json research/voc/data/ios_ratings.json
python -I research/voc/scripts/analyze.py research/voc/data research/voc/out
```
