> **이 리포트를 근거로 인용할 때**
> - 비중(%)은 **부정 리뷰(1~2점) 안에서 해당 불편이 언급된 비율**이다. 한 리뷰가 여러 불편에 걸릴 수 있어 합이 100%가 아니다.
> - 리뷰를 쓰는 사람은 불만층에 치우쳐 있다(6-7절). "운전자 전체의 N%"로 인용하지 말고 **"앱 리뷰에서 불만을 말한 사용자 중 N%"** 로 인용한다.
> - 각 카테고리의 신뢰도는 5-3절 정밀도 표를 함께 확인한다. 정밀도 '낮음' 카테고리는 수치를 인용하지 않는다.
> - **키워드 분류의 비중은 '하한값'이다.** Gemini 판정과 비교하면 키워드 분류는 실제 언급의 20~40%만 잡는 카테고리가 많다(5-4절). **"얼마나 자주 언급되는가"는 6-9절 Gemini 추정치를 우선 인용**하고, 키워드 수치는 추이(연도별 변화) 비교에만 쓴다.

## 1. 핵심 결과

1. **어느 그룹이든 1순위 불만은 '앱 그 자체'다.** 부정 리뷰의 약 25%가 앱 오류·먹통·느림, 20%가 UI·UX, 12%가 로그인 문제다. 기능이 아니라 **기본 품질과 속도**가 가장 큰 불만이다.
2. **충전 앱에서 요금 불만이 2026년에 두 배로 늘었다.** 충전 앱 부정 리뷰 중 요금·가격 언급은 2021~2025년 9~12% 수준에서 **2026년 21.4%** 로 뛰었다. 내용은 요금 인상, 아파트 완속 요금 격차(같은 전기 145~320원), 로밍·비회원가다.
3. **충전 앱은 극단적으로 양극화돼 있다.** 여러 사업자를 묶고 혜택을 주는 통합 앱(일렉베리 4.79, EVSIS 4.73, 모두의충전 4.61)은 사랑받고, 아파트에 설치돼 어쩔 수 없이 쓰는 사업자 앱(이지차저 1.43, 파워큐브 1.57, 차지비 1.59, KEPCO PLUG 1.80)은 미움받는다. **이 패턴은 iOS 전체 평점(글을 안 쓴 사용자 포함)에서도 똑같이 나타난다.**
4. **회원가를 받기 위한 가입·카드 장벽이 독립된 불편이다.** 충전 앱 부정 리뷰의 18%가 로그인·인증, 4.4%가 카드 등록·결제 오류다. 가입이 실패하면 최대 2배인 비회원가를 내야 한다.
5. **리워드는 반응이 좋지만, 줄이거나 막으면 강하게 반발한다.** 리워드 언급 리뷰 894건의 평균 별점은 4.48로 매우 높다. 그러나 포인트 전환 불가(공감 196), 혜택 축소("km당 10원 → 5원"), 주행 리워드 기능의 무공지 삭제에는 1점 리뷰가 몰린다.
6. **현대차그룹 앱은 2025년 통합 이후 큰 반발을 겪고 2026년에 회복 중이다.** 블루링크·기아 커넥트가 마이현대·Kia App으로 통합된 2025년, 리뷰 평균이 1.9~2.0점까지 떨어졌다(공감 4,366개 리뷰 등). 2026년에는 약 3.0점으로 회복했다. 불만의 핵심은 느린 반응, "1초 길게 누르기", 늘어난 메뉴였다.
7. **리뷰를 쓰는 사람은 불만층이다.** 마이현대는 전체 평점이 Play 4.75·iOS 4.48인데 리뷰 본문 평균은 2.28이다. 리뷰 분석은 "무엇이 불만인가"를 찾는 도구이지 "얼마나 많은 사람이 불만인가"를 재는 도구가 아니다.

**Gemini 감성분석으로 추가로 확인한 것**

8. **충전 앱에서 요금과 리워드는 '불만'이 아니라 '가치'로 더 많이 언급된다.** 충전 앱 리뷰의 10.1%가 요금을 언급하는데 그중 **63%가 긍정**("가격비교가 한번에", "할인이 많고")이다. 리워드는 13.2%가 언급하고 **89%가 긍정**이다. 요금을 아껴주고 보상을 주는 기능이 국내 충전 앱 만족의 핵심 동인이다.
9. **별점과 글의 감성이 어긋나는 리뷰가 9%다.** 4~5점인데 글은 부정·혼합인 리뷰가 8.9%(내비 21.9%). 반어 2.1%, 개선 요청 포함 27.1%. 별점만으로 감성을 판단하면 이만큼 놓친다.

> 해외와 비교한 결과(리워드는 한국 특유의 경쟁 축, 유럽판 통합 앱 반발 등)는 ③ [비교 요약](앱리뷰-VOC-국내해외-비교.md) 참조.

## 5. 분류 체계와 정확도 검증

### 5-1. 방법
- **키워드(정규식) 기반 다중 라벨 분류.** 리뷰 본문에 패턴이 있으면 해당 카테고리 True. 한 리뷰가 여러 카테고리에 걸릴 수 있다.
- 형태소 분석기 대신 정규식을 쓴 이유: 한국어 리뷰의 구어체·오타·띄어쓰기 변형이 심해, `\s*`로 띄어쓰기 변형을 흡수하는 쪽이 재현성과 수정 용이성이 높다.
- 패턴 정의: `research/voc/scripts/taxonomy.py`

### 5-4. Gemini 속성 기반 감성분석

키워드 분류는 ① 리뷰 글의 감성을 보지 않고(별점으로 대신함) ② 반어·엇갈린 감성을 처리하지 못하며 ③ 패턴 밖 표현을 놓친다. 이를 보완하려고 LLM으로 **리뷰별 전체 감성 + 카테고리별 감성**을 판정했다.

| 항목 | 설정 |
|---|---|
| 모델 | Google Gemini 무료 API. `gemini-3.5-flash`로 시작했으나 무료 한도로 175건 이후 `gemini-3.5-flash-lite`로 자동 전환 → **93%가 flash-lite** |
| 방식 | 요청 1회에 리뷰 25건, 온도 0, JSON 스키마 강제(`responseSchema`) |
| 출력 (리뷰별) | `overall`(긍정·부정·중립·혼합), `sarcasm`(반어), `request`(개선 요청 포함), `aspects`[카테고리, 감성, 근거 원문 30자 이내] |
| 카테고리 | 키워드 분류와 같은 18개 + **"충전 인프라(충전소 수·위치·속도)"**, "기타" |
| 프롬프트 | 카테고리 정의, 반어 예시, "별점이 아니라 글 내용으로 판단" 지시 포함 (`scripts/llm_absa.py`) |
| 코드 | `scripts/gemini_client.py`(키는 `research/voc/.env`에서만 읽음), `llm_sample.py`, `llm_absa.py`, `llm_eval.py` |

**표본 설계**

| 표본 | 건수 | 구성 | 용도 |
|---|---:|---|---|
| 국내 main | 2,400 | 충전 앱 1,000 / 현대차그룹 700 / 경쟁 완성차 500 / 내비 200. 그룹 안에서 앱 비례(앱당 최소 보장), 최근 1년 비중 확대 | 비중 추정 — **(그룹, 앱, 최근 여부) 층 가중치** 적용 |
| 국내 boost | 295 | 리워드 키워드 150 + 충전 앱 요금 키워드 145 | 리워드·요금 감성 심층 (비중 추정에는 안 씀) |

**검증 1 — 사람 판독 vs Gemini.** Gemini 결과를 보기 **전에** 판독자(Claude)가 블라인드로 50건에 라벨을 달고 비교했다.

| 지표 | 결과 (50건) |
|---|---:|
| 전체 감성 일치 | **90.0%** |
| 카테고리 정밀도 (Gemini가 단 카테고리 중 사람과 일치) | 81.4% |
| 카테고리 재현율 (사람이 단 카테고리 중 Gemini가 잡은 비율) | 82.8% |
| 공통 카테고리의 감성 일치 | 93.8% |

불일치는 대부분 경계 사례였다: 기능 요청을 사람은 '중립', Gemini는 '부정'으로 본 경우("다른 계정으로도 로그인하게 해 주세요"), "좋은데 어제부터 앱이 죽네요"를 사람은 '혼합', Gemini는 '부정'으로 본 경우.

**검증 2 — 키워드 분류 vs Gemini (main 2,400건, Gemini를 기준값으로)**

| 카테고리 | Gemini 판정 | 키워드 판정 | 키워드 정밀도 | 키워드 재현율 |
|---|---:|---:|---:|---:|
| 앱 안정성·오류 | 584 | 406 | 54.7% | **38.0%** |
| UI·UX 불편 | 445 | 271 | 52.0% | **31.7%** |
| 원격제어·차량연결 | 383 | 195 | 79.5% | 40.5% |
| 로그인·인증 | 238 | 190 | **91.6%** | **73.1%** |
| 요금·가격 | 150 | 171 | 50.9% | 58.0% |
| 포인트·리워드·멤버십 | 141 | 87 | 85.1% | 52.5% |
| 고객센터·응대 | 109 | 89 | 78.7% | 64.2% |
| 결제·청구 오류 | 107 | 33 | 78.8% | **24.3%** |
| 충전기 정보 부정확 | 99 | 2 | — | **1.0%** |
| 충전기 고장·충전 실패 | 81 | 21 | 76.2% | **19.8%** |
| 디지털키 | 58 | 49 | **91.8%** | **77.6%** |
| 배터리·전비 | 29 | 68 | 10.3% | 24.1% |

해석:
- **키워드 분류는 대부분의 카테고리를 크게 과소 집계한다** (재현율 20~40%). 특히 충전기 정보·고장·결제 오류는 표현이 다양해 정규식으로 잡기 어렵다.
- 로그인·디지털키처럼 **고유 단어가 있는 주제만** 키워드로도 정확하다.
- 키워드 정밀도가 50% 전후인 이유 중 하나는 Gemini가 "더 구체적인 카테고리 하나만" 고르도록 지시받았기 때문이다(예: "앱이 느려서 원격시동이 늦다"를 Gemini는 원격제어로만, 키워드는 둘 다로). 따라서 이 정밀도는 키워드 분류의 오류율이 아니라 **두 방식의 기준 차이**를 포함한다.
- 결론: 연도별 **추이**는 같은 방식으로 잰 키워드 수치로 보고, **수준(얼마나 많은가)** 은 Gemini 추정치(6-9절)로 본다.

| 아파트 완속은 사업자 lock-in | 요금 최적화의 대상은 **공용·외부 충전**. 집 충전은 "비교·알림" 수준 |
| 통합·혜택형 앱만 사랑받음 | 특정 사업자 편이 아닌 **중립적 통합 추천**이어야 신뢰를 얻음 |
| 가입·카드 장벽 (로그인 18%) | **"내가 가진 멤버십 기준 최저가"** 추천. 새 가입을 요구하지 않음 |
| 리워드 반응 좋음, 축소엔 반발 | 리워드 유지. **가치 안정성·쉬운 사용처·긴 유효기간**을 설계 원칙으로 |
| 캐시백 드라이빙의 수동 기록 오류·삭제 | **차량 Odometer 자동 검증** = 핵심 차별점. 동시에 **지속 가능한 재원**(수요 분산 대가 등)이 없으면 기능이 사라진다는 경고 |
| 경로상 충전소 기능 요청 | NaviHelper 경유지 추가로 구현 (스파이크에서 경로 요청 동작 확인) |
| 통행료·대기 지루함·전비 원인 근거 없음 | 통행료 합산, 충전 대기 게임, 전비 원인 설명은 **축소·재설계** |
| 충전 앱에서 요금 언급의 63%, 리워드 언급의 89%가 긍정 | "아껴주고 보상하는 기능"이 이미 검증된 만족 동인. A+의 방향과 일치 |
| "충전소에서 적용 가능한 멤버십이 표시되면 좋겠다" | "내가 가진 멤버십 기준 최저가" 기능의 직접적 수요 근거 |

> 해외 근거를 함께 쓴 기획 시사점(차량 연결 실패, 한국 특화 리워드 등)은 ③ [비교 요약](앱리뷰-VOC-국내해외-비교.md)에 있다.

### 8-2. 설계 원칙 (현대차그룹 앱 통합 반발에서 배운 것)
1. **자주 쓰는 동작은 첫 화면, 한 번의 터치.** "한 단계 더 들어가야 하고 또 한 단계"에 공감 2,705.
2. **느리면 안 된다.** "시동 버튼 누르기까지 몇 초"에 공감 730. Pleos 심사 기준(터치 반응 0.25초, 버튼 2초)과 일치.
3. **정보 노출보다 행동.** "정보를 보여주는 쪽에 더 집중"에 공감 4,366. 차 화면에서는 더더욱 한 가지 행동을 제안하는 화면이 맞다.
4. **기존 습관을 깨지 않는다.** 통합 앱 불만의 상당수가 "예전 앱이 더 좋았다". 새 기능은 기존 흐름(내비) 안에 녹인다.

### 8-3. 기획서에 인용하기 좋은 수치
- "충전 앱 리뷰에서 요금 불만은 2025년 12.0%에서 2026년 21.4%로 늘었다" (부정 리뷰 기준)
- "같은 완속 충전이 아파트에 따라 kWh당 145~320원" (리뷰 원문 사례 — 공식 수치는 소비자원 270~590원 사용)
- "통합·혜택형 충전 앱 iOS 평점 4.4~4.8 vs 사업자 전용 앱 1.3~2.0"
- "리워드를 언급한 리뷰의 평균 별점 4.48 (분석 대상 전체 평균 2.72)"
- "주행거리 기반 리워드(캐시백 드라이빙)는 수동 기록 오류와 혜택 축소 끝에 사전 공지 없이 삭제됐다"
- "충전 앱 리뷰 중 리워드를 언급한 비율은 13.2%, 그중 89%가 긍정" (Gemini 추정)
- "4~5점 리뷰 중 약 9%는 실제로는 불만이나 요청을 담고 있다"

## 9. 한계와 신뢰도

| 한계 | 영향 | 대응 |
|---|---|---|
| **리뷰 작성자 편향** — 불만층이 글을 쓴다 (6-7절) | 불편의 "규모"를 과대평가 | 비중은 "불만층 안의 상대 순위"로 인용. 규모는 공식 설문 사용 |
| **채널 편향** — 앱 밖의 불편(충전기 고장, 대기)은 앱 리뷰에 덜 나온다 | 고장·대기 비중 과소평가 (설문에서는 고장 52.7%가 1위) | 공식 조사·커뮤니티와 함께 판단 |
| **App Store 표본 부족** — 앱당 약 10건, 무작위 아님 | iOS 사용자 관점 약함 | iOS 전체 평점 통계로 앱 평가 보완, 인터뷰에 아이폰 사용자 포함 |
| **키워드 분류의 오차** | 비중에 ±수 %p 오차 | 5-3절 정밀도 검증, 낮은 카테고리는 인용 제외 |
| **정밀도 판정자 1명·표본 12건** | 정밀도 자체가 대략치 | 핵심 수치(요금)는 별도로 18건 확인 |
| **라벨 커버리지 64%** — 부정 리뷰 36%는 분류 안 됨 | 일반 불만("최악")이 빠짐 | 비중은 분류된 불편 간 비교로 사용 |
| **키워드 재현율이 낮음** (20~40%) | 키워드 비중은 실제보다 낮음 | Gemini와 비교해 측정(5-4절). 수준은 Gemini 추정치로 인용 |
| **개발사 답변·앱 버전 미분석** | 대응 품질·버전별 품질 미반영 | 데이터는 수집돼 있음 (`reply`, `app_version`) |
| 리뷰 수정 시 Play는 최신본만 | 시점 왜곡 가능 | 연도 추이는 경향으로만 해석 |
| **Gemini 모델 혼용** — 무료 한도로 대부분 flash-lite | 더 큰 모델보다 판정 정밀도가 낮을 수 있음 | 사람 판독 50건으로 정확도 측정 (5-4절). 유료 키로 재실행하면 개선 가능 |
| **사람 판독자 1명** (Claude), 블라인드 | 판독 기준 자체의 편향 | 실제 사람(프로젝트 팀원) 2명이 같은 50건을 판독해 교차 검증하면 신뢰도↑ |
| LLM 표본 2,400건 | 소규모 카테고리(대기, 미출차 등)는 추정 불안정 | n<30 카테고리는 비중 인용 금지 |
| Gemini 무료 티어 | 입력이 Google 서비스 개선에 쓰일 수 있음 | 공개 리뷰만 전송. 인터뷰 녹취 등 비공개 자료는 보내지 않음 |

## 10. 재현 방법과 데이터 사전

### 10-1. 파일 구조
```
research/voc/
├── scripts/
│   ├── apps.py          # 수집 대상 38개 앱 (그룹·이름·Play ID), 앱당 상한
│   ├── find_apps.py     # Play 검색으로 앱 ID 후보 찾기
│   ├── collect_play.py  # Play 리뷰 수집 (앱별 JSONL, 완료 앱 건너뜀)
│   ├── find_ios.py      # iTunes Search API로 iOS 앱 ID 찾기
│   ├── collect_ios.py   # App Store 공개 리뷰 페이지 수집 (앱당 약 10건)
│   ├── ios_ratings.py   # iTunes Lookup API로 iOS 전체 평점·평가 수
│   ├── taxonomy.py      # 불편 18개 + 가설 7개 패턴 (v2)
│   ├── analyze.py       # 전처리·분류·집계·인용문 추출
│   ├── gemini_client.py # Gemini REST 호출 (키는 ../.env에서만 읽음)
│   ├── llm_sample.py    # 국내 LLM 표본 (main 2,400 + boost 295, 층 가중치)
│   ├── llm_absa.py      # Gemini 속성 기반 감성분석 (25건 배치, 재실행 시 이어서)
│   └── llm_eval.py      # 사람 판독·키워드 대비 검증, 감성·카테고리 집계
├── data/
│   ├── app_search.json, ios_search.json   # 앱 ID 검색 결과
│   ├── play/{appId}.jsonl                 # Play 원본 141,767건
│   ├── play/_play_meta.json               # Play 앱 정보 (전체 평점·평가 수·설치 수)
│   ├── ios/{appId}.ios.jsonl              # App Store 원본 376건
│   └── ios_ratings.json                   # iOS 전체 평점
├── .env                 # GEMINI_API_KEY (git 제외, 직접 열어보지 않음)
└── out/
    ├── llm_sample.csv / llm_results.jsonl / llm_merged.csv   # 국내 Gemini 표본·결과
    ├── llm_eval.json            # 사람 vs Gemini, 키워드 vs Gemini, 감성 요약, 리워드·요금 심층
    ├── llm_aspects_by_group.csv # 국내 그룹 × 카테고리 언급률·감성
    ├── human_val_items.csv / human_val_labels.json  # 국내 블라인드 판독 50건
    ├── classified_reviews.csv   # 분석 대상 32,662건 + 라벨
    ├── apps_overview.csv        # 앱별 리뷰 수·평균·부정 비율·최근 1년
    ├── ratings_vs_reviews.csv   # 전체 평점(Play·iOS) vs 리뷰 본문 평균
    ├── pain_by_group_all.csv / pain_by_group_recent.csv
    ├── summary.json             # 연도 추이·가설·스토어별·앱별 상위 불편
    └── quotes.json              # 카테고리·가설별 공감 상위 리뷰
```

### 10-2. 재실행
```bash
python -m venv .venv && .venv/bin/pip install google-play-scraper pandas
.venv/bin/python -I research/voc/scripts/collect_play.py research/voc/data/play
.venv/bin/python -I research/voc/scripts/collect_ios.py research/voc/data/ios_search.json research/voc/data/ios
.venv/bin/python -I research/voc/scripts/ios_ratings.py research/voc/data/ios_search.json research/voc/data/ios_ratings.json
.venv/bin/python -I research/voc/scripts/analyze.py research/voc/data research/voc/out

# Gemini 감성분석 (research/voc/.env 에 GEMINI_API_KEY=... 필요)
.venv/bin/python -I research/voc/scripts/llm_sample.py research/voc/out/classified_reviews.csv research/voc/out/llm_sample.csv
.venv/bin/python -I research/voc/scripts/llm_absa.py research/voc/out/llm_sample.csv research/voc/out/llm_results.jsonl
.venv/bin/python -I research/voc/scripts/llm_eval.py research/voc/out


```
- Gemini 실행은 무료 한도에 걸리면 `flash-lite`로 자동 전환되고, 그마저 막히면 멈춘다. 같은 명령을 다시 실행하면 **완료된 리뷰는 건너뛰고 이어서** 진행한다.
- 표본을 다시 뽑으면(`llm_sample.py`) 사람 판독 50건의 uid가 바뀔 수 있으니 기존 `human_val_*` 파일과 함께 관리한다.
- 수집을 다시 하려면 `data/play/*.done` 파일을 지운다 (없으면 해당 앱을 건너뜀).
- 분류 패턴만 바꿨다면 `analyze.py`만 다시 돌리면 된다.
- 앱을 추가하려면 `apps.py`의 `APPS`에 `(그룹, 이름, Play ID)`를 넣고, iOS는 `find_ios.py`의 `TERMS`에 검색어를 추가한다.

### 10-3. `classified_reviews.csv` 열 정의

| 열 | 설명 |
|---|---|
| `group_ko` | 그룹 (현대차그룹 / 경쟁 완성차 / 충전 앱 / 내비(EV 리뷰만)) |
| `app` | 앱 이름 |
| `store` | `play` / `ios` |
| `score` | 별점 1~5 |
| `thumbs_up` | 공감 수 (iOS는 0) |
| `at` | 작성일시 (UTC 기준, 시간대 제거) |
| `content` | 리뷰 본문 (iOS는 제목 + 본문) |
| 불편 18개 열 | 해당 불편 언급 여부 (True/False) |
| `H1`~`H6a` 7개 열 | 가설 패턴 해당 여부 (True/False) |

엑셀에서 열 때 UTF-8 BOM이 있어 한글이 깨지지 않는다.

### 10-4. 다음에 할 수 있는 분석
- **사람 판독자 추가** — 팀원 2명이 같은 50건을 판독해 판독자 간 일치도(코헨 카파) 측정
- **유료 모델로 재분류** — flash-lite 대신 상위 모델로 같은 표본을 다시 돌려 차이 확인
- **개발사 답변 분석** — 앱별 답변률·답변 속도와 별점 관계
- **앱 버전별 분석** — 특정 업데이트 전후 불만 변화
- **긍정 리뷰 분석** — 사용자가 "좋다"고 말하는 기능 (통합 충전 앱의 성공 요인)
